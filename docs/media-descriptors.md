# Pure media descriptors (not yet wired to MCP tools)

`extractMediaReferences({html, source, rights?})` is an async pure helper. It returns `media`, a compatibility `image_url` pointing to the first recognized `img`, `status`, and `issues`. It does not fetch anything, rewrite the input HTML, change existing get/browse output, resolve localization IDs, or claim catalog completeness. Integration is a separate reviewed change.

`source` requires organization, resourceCode, contentId, actual content language, a full 40-character revision, contentPath beginning with that language, contentFileSha256 and articleHtmlSha256. The caller must verify the complete source JSON file and supply its hash. This helper validates hash format and independently recomputes the exact HTML hash; it cannot verify whole-file bytes that were not passed to it. These are separate hashes. Relative media references resolve against the explicit pinned content file location, never `main`; relative references escaping the pinned repository revision are rejected. Explicit external HTTP(S) references remain external. No requested-language fallback is performed.

Each descriptor retains modality, resolved URL, every original/decoded attribute and tag occurrence, and source provenance. Equal modality+resolved URL references are grouped without losing original spellings. Exact query strings and fragments remain significant. `bytes`, `durationSeconds` and `assetSha256` are null. `playable` and asset rights are unverified; narrator is unknown. A collection rights statement/metadata URL can be carried, explicitly collection-scoped, but is not promoted to audio-specific permission. A source string such as `(2502188 KB)` is never interpreted as a measured size.

Supported syntax: audio/video `src`, nested audio/video `source src`, video poster, img src, and anchors explicitly identified by audio/video/image MIME type or recognized file extension. Ambiguous `.ogg` anchors need an explicit media MIME type; audio/video tags already declare their modality. Arbitrary links, Drive folder links, CSS URLs, scripts, comments and raw text containers do not become media. Images in `picture/srcset` and extensionless links without media MIME are outside this bounded helper; callers must not interpret the result as all possible browser-renderable media. HTTP(S) only, no URL credentials or control/space characters. No HTML is executed.

This uses a conservative local tag/attribute scanner, not a browser HTML parser or sanitizer. Unterminated/ambiguous markup, unsafe recognized references, orphan sources, and resource limits return `partial` with explicit issues. Valid references discovered before an issue remain available. A clean empty result means no references in the supported syntax, not proof a publisher has no recordings. Limits: two million HTML characters and one thousand distinct descriptors. Source binding errors throw and return no result.

The existing get text and image behavior remain unchanged because no tool integration occurs here. A future catalog integration must combine this article-level scan status with its own file/page completeness, validate real requested-language rows, and expose the difference between incomplete and empty. Official external FIA distribution is not crawled or inferred by this helper.
