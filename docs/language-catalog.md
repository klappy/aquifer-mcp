# Standalone language catalog (integration pending)

`buildLanguageCatalog` accepts an immutable identity, a pinned discovery result, an injected content reader and optional continuation state. It performs no fetch/storage itself. The reader must use `pinnedCatalogUrl` or an equivalent exact-revision fetch and enforce its maxBytes request; returned path/revision are checked and original UTF-8 bytes hashed before JSON parsing. Returning bytes merely labelled with a revision does not prove a live pinned fetch. That proof belongs to the integration's network tests/readback.

Discovery must provide actual language/json content paths and an exhaustive flag with method git-tree or metadata. Probe lists cannot be exhaustive. Truncated trees or discovery issues remain incomplete; expectedFiles is null when the global count is unknown. Paths are sorted/deduplicated; articles retain source order. A missing file or read error differs from valid empty JSON arrays. Source HTML and associations are preserved. An absent language field uses explicit source-path provenance; a conflicting field is rejected. Identical duplicate IDs deduplicate; conflicting IDs are quarantined and prevent completion.

Each entry supplies contentFileSha256 and articleHtmlSha256 separately for the media bridge. Explicit localization metadata may provide aliases only when its revision/path are valid and its target exists in verified content. Its original bytes are hashed. Primary IDs never create localized entries; aliases never shadow an actual content ID. Collection rights and media descriptors are supplied by separate integration stages.

Default budget is4 files/2,000,000 bytes, hard maximum32 files/8,000,000 bytes per invocation, sequential reader concurrency1. Reader must avoid unbounded downloads before returning. A response violating the byte budget is failed and stops that invocation. Failed sources are not silently retried. Start a new scan after a transient failure, or supply a new verified revision; previous incomplete envelopes are preserved.

Continuation requires both prior envelope and opaque cursor. Cursor binds schema, identity, revision, discovery list, query/filter key and prior-state digest. It detects stale/mismatched state; it is not an authentication signature. Cached envelopes must retain all fields. Version2 `pinned-content`, `pinned-metadata`, `pinned-catalog` keys intentionally do not reuse old SHA-labelled main-fetch caches. These helpers are not yet wired into existing fetch code.

`languageCatalogPage` pages known entries separately from scan continuation and marks totals exact only when complete. `complete` requires exhaustive discovery, all known files scanned, no failures/conflicts/issues. An empty partial page cannot establish absence. A completed supported source scan says nothing about external FIA/Drive distribution. No external provider is queried here.
